Нагрузка во времени: k6 в Grafana

Load over time: k6 in Grafana

Итог k6 говорит «сколько»: 27 088 запросов, p95 0.7 мс. Но не говорит «когда»: росла ли задержка вместе с нагрузкой, с какого числа пользователей пошли ошибки, медленной была первая минута или последняя. Для этого метрики хранятся как временные ряды в Prometheus и рисуются в Grafana, а после прогона панели сохраняются картинками на GitHub Pages.

k6's summary says "how much": 27,088 requests, p95 0.7 ms. It doesn't say "when": did latency grow with the load, at what number of users did errors start, was the first minute slow or the last. For that the metrics are stored as time series in Prometheus and drawn in Grafana, and after the run the panels are saved as pictures on GitHub Pages.

02

Почему перцентили нельзя усреднять

Why percentiles can't be averaged

Два эндпоинта: быстрый (p95 = 1 мс) и медленный (p95 = 100 мс). Двигайте долю медленных запросов и сравните «среднее двух p95» с настоящим p95 всех запросов. Нативные гистограммы хранят само распределение, поэтому Prometheus считает настоящий.

Two endpoints: a fast one (p95 = 1 ms) and a slow one (p95 = 100 ms). Move the share of slow requests and compare "the average of two p95s" with the real p95 of all requests. Native histograms keep the distribution itself, so Prometheus computes the real one.

03

Закрытая модель меряет сценарий, а не сервер

A closed model measures the script, not the server

В stress-профиле график запросов в секунду упёрся в 240 и стоял ровно. Это не предел каталога: каждый виртуальный пользователь делает 4 запроса и спит секунду. Посчитайте.

In the stress profile the requests-per-second graph hit 240 and stayed flat. That's not the catalogue's limit: each virtual user makes 4 requests and sleeps a second. Do the maths.

04

Имя у каждого запроса

A name for every request

k6 метит запросы адресом. /catalogue/3395a43e-… для каждого носка и /carts/<id>/items для каждого нового покупателя — это отдельные временные ряды. Тег name сводит их к эндпоинтам.

k6 labels requests by URL. /catalogue/3395a43e-… for every sock and /carts/<id>/items for every new customer are separate time series. The name tag folds them into endpoints.
